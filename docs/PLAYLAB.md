# MatchFIT PlayLab

Design, permutate, validate and score **gamified football drills as structured game
systems** — a lean MVP of the MatchFIT session-planning platform.

## Problem

Existing football drill libraries list drills but do not help coaches design game
mechanics, test rule permutations, or understand how drill actions affect points and
player progression.

## Solution

PlayLab combines session planning, drill generation, rule configuration, game scoring,
XP mapping, live execution and post-session iteration in one workflow:

```
Open session → view drills → analyse balance → create/remix a drill
→ configure rules → configure points & XP → preview player flow
→ add to session → run live scoring → record results → leaderboard
```

## Run it

```bash

npm install
npm run setup     # prisma generate + db push (SQLite) + seed
npm run dev       # site at :3000, PlayLab at :3000/playlab
```

Other scripts: `npm test` (18 engine unit tests), `npm run typecheck`, `npm run build`,
`npm run seed` (re-seed from scratch).

No authentication — a single demo coach account is assumed throughout.

## Demo walkthrough (acceptance flow)

1. Open `http://localhost:3000/playlab` → redirects to the seeded session (30 Jul 2026, KNC BaseCamp).
2. See the three selected drills (Football Tic-Tac-Toe, Passing Gate Challenge, Six-Goal Finish) and the **Session balance** panel with missing/adequate/over dimensions and a generated insight.
3. Click **Create new MatchFIT drill** → complete the six-step builder (purpose, experience, format, mechanics, constraints).
4. **Generate concepts** → three distinct concepts (Reliable / Most MatchFIT / Experimental), each with selection score, flow estimate and session-fit explanation. Same inputs always generate the same concepts (seeded RNG).
5. **Select → Rule Studio** — the concept is saved as an `aiDraft` drill and opened in the Rule Permutation Studio.
6. Change rule parameters (e.g. `maxTouches` 3 → 2) — complexity, difficulty, success rate, flow and the round simulation update instantly.
7. Enable **Unlimited touches** together with **Limited touches** → a **blocking** conflict appears in the Compatibility panel. Enable **Weak-foot streak bonus** without **Weak-foot attempts** → dependency warning.
8. Edit **Drill score** events (who wins this game) and **MatchFIT XP** rules (long-term progression) — the two systems are visibly separate.
9. Use the **Round simulation** panel (add goal / correct target / weak-foot / streak / round win) — see drill points and XP calculated separately with a line-by-line breakdown (the seeded Colour Call Finish reproduces the spec's 8-point / 45-XP example).
10. Check **Player flow** (rounds, attempts/player, waiting, participation, healthy/moderate/poor) and XP guardrail warnings.
11. **Save & approve**, go back to the session → **Session Builder** tab → drag to reorder the timeline, edit durations, watch intensity sequencing and transition warnings.
12. Sidebar → **Live Scoring** → pick a drill → tap players/teams and the event buttons (generated from the active scoring rules), undo, next round, **End drill**.
13. Submit the **post-session review** → a recommendation is generated from your scores, the drill's status moves to `verified` or `needsModification`, and player XP totals update.
14. Open **Leaderboard** → updated XP standings.

## Architecture

```
src/app/(playlab)/   PlayLab routes at /playlab (second root layout beside the main site)
src/playlab/components/  Client components (session view, wizard, rule studio, live panel)
src/playlab/lib/     The engines — pure TypeScript, no React:
  session-analysis.ts   what the selected drills overuse/omit + insight text
  drill-generator.ts    deterministic template-based concept generation (seeded)
  rule-engine.ts        conflicts, dependencies, impossible combinations
  scoring-engine.ts     drill points from events + rules
  xp-engine.ts          XP from events + anti-inflation guardrails
  player-flow.ts        rounds / attempts / waiting / participation maths
src/playlab/store/   Zustand stores (drill builder wizard, live scoring)
prisma/              schema (SQLite) + seed (18 players, 3 teams, 14 drills, 1 session,
                2 AI drafts generated by the real engine, 1 verified drill + review)
src/playlab/types/   Shared domain types
```

- **Frontend state**: server components fetch; interactive screens hold local state
  (Zustand for the wizard and live mode) and persist via server actions.
- **Database**: SQLite via Prisma. Swap `provider = "postgresql"` in
  `prisma/schema.prisma` to upgrade — no JSON-blob drills; rules/scoring/XP are
  relational rows (flexible value maps live in `*Json` string columns because SQLite
  lacks a JSON type).
- **Future AI integration point**: `lib/drill-generator.ts` exposes
  `DrillConceptProvider` — implement `generate(input)` with a model call and swap it
  for `localDrillProvider`. The UI and persistence don't change.

## Known limitations

- Single coach, no auth, no multi-tenant anything (by design for the MVP).
- Live mode awards participation XP only to players with at least one recorded event.
- Team XP spreads `roundWin` teamwork XP at completion; other team-level XP categories attach to the team, not players.
- The `/` route bakes its redirect at build time (fine while the seeded session id is stable).
- Drag-and-drop uses native HTML5 events — fine on desktop, use the arrow buttons on touch devices.

## Phase 2 roadmap

2. PostgreSQL + auth + clubs/squads multi-tenancy.
3. Drill versioning: keep each permutation as a diff, compare test reviews across versions.
4. Player-level skill telemetry feeding `playerNeeds` into selection automatically.
5. Session XP budget dashboard reconciling planned vs earned XP.
6. Video/content capture prompts tied to `contentMoment`.
